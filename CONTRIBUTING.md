# Contributing

1. Identify or open an issue describing the problem.
2. Create a short-lived branch from `main`.
3. Make a focused change and update related links.
4. Run relevant checks locally.
5. Open a pull request using the template.
6. Address review feedback and record unresolved trade-offs.
7. Merge only when acceptance criteria are met.

## Expectations
- Prefer actionable guidance over slogans.
- Distinguish requirements, recommendations and examples.
- Cite primary sources and include publication dates where known.
- Do not present one organisation's practice as universal.
- Do not copy third-party repositories or documents wholesale.
- Preserve attribution and comply with licences.
- Never commit secrets, credentials, personal data or confidential client material.

## Definition of done
- [ ] Problem and audience are clear.
- [ ] Guidance is actionable and proportionate.
- [ ] Claims are sourced or labelled as opinion/assumption.
- [ ] Links and cross-references are checked.
- [ ] Security, privacy, accessibility and maintenance are considered.
- [ ] Relevant templates are updated.
- [ ] PR explains the change and validation evidence.
