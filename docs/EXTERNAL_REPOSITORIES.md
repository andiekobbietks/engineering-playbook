## Repository adoption record

Before adopting a third-party project, record:

- Exact repository URL and pinned release/commit
- Maintainer and maintenance activity
- Licence and obligations
- Security advisories and dependency health
- Compatibility, architecture and operational fit
- Data handling and telemetry
- Exit/replacement plan
- Local modifications and upstream contribution strategy

## Reuse rules

- **Link by default.** Use the upstream project and preserve its issue history, releases and attribution.
- **Fork only with a reason.** Record why a fork is needed, how it will be maintained and how upstream changes will be reconciled.
- **Submodule or subtree only for a real dependency.** Document pinning and update responsibilities.
- **Never bulk-copy repositories** into this playbook merely to create a central catalogue. That creates licence, provenance, security and maintenance problems.
- If code is adapted, retain licence notices and comply with the upstream licence. Do not imply affiliation or endorsement.

The purpose of this file is a curated index. Each selected project should later receive a source-level assessment before it is recommended.
